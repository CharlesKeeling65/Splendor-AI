The T1.4 crossed pilot keeps the engine score-delta reward and the terminal
utility fixed while changing exactly one shaping boundary condition.

| Treatment | Reward version | Terminal utility | `gamma` | `kappa` | Shaping terminal potential | Claim |
|---|---|---:|---:|---:|---:|---|
| `O_bridge` | `terminal-biased-potential-v1` | `+10 / 0 / -10` | 0.99 | 0.05 | observed `Phi(s_T)` | historical bridge; not policy-invariant |
| `O` | `safe-potential-v1` | `+10 / 0 / -10` | 0.99 | 0.05 | `0` | episodic PBRS contract |

The shaping term for transition `t` is

```text
F_t = gamma * Phi(s_(t+1)) - Phi(s_t)
```

and therefore, under the trainer's discounted return,

```text
sum_(t=0..T-1) gamma^t F_t
    = -Phi(s_0) + gamma^T Phi(s_T).
```

`safe-potential-v1` treats the successor of every episode-ending transition as
the absorbing state with `Phi(s_T)=0`. This includes normal score termination,
all-pass deadlock, the engine round limit, and a runner/environment truncation.
The safe shaping contribution is consequently always `-Phi(s_0)`, independent
of the final observed position. The `+10 / 0 / -10` outcome utility remains a
separate additive terminal signal and is not changed by this correction.

The unqualified Python constructors `PotentialRewardShaper()` and
`PotentialShapingWrapper(...)`, and the existing DQN `--shaping potential`
entry, intentionally retain `terminal-biased-potential-v1`. Formal T1.4 code
must select `SAFE_POTENTIAL_CONTRACT` explicitly and persist its version string;
silently changing a legacy default would invalidate `O_bridge` and historical
C2-R2 comparisons.

Raw-engine loops infer engine termination through `rule.gameEnds()`. A
runner-imposed truncation must call `advance(..., episode_ended=True)` or
`finish(...)`. Gym wrappers consume `terminated or truncated` and therefore
close both paths automatically.
