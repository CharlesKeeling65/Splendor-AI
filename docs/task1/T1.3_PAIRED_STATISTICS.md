# T1.3 — 配对评测、聚类统计与固定样本量协议

日期：2026-09-15
状态：实现与离线合成验收完成；未运行 pilot、未读取正式 validation/sealed bank、未启动训练。

## 1. 正式评测矩阵

实现：`policy_imitation/paired_evaluation.py`。

`PairedEvaluationSpec` 只接受完整物化且重新认证过的 `ScenarioBank`，并按内容 hash
排序后生成固定笛卡尔积：

```text
candidate checkpoint/source × opponent snapshot/source × scenario_id × seat [0, 1]
```

每个 checkpoint、无权重 built-in policy 和 opponent 都必须有 64 位内容身份。
checkpoint 身份会与实际文件 SHA-256 复核，并另外从 checkpoint tensor state、factory
绑定的冻结 module、以及实际构造的 seat 0/1 两个 agent 的 `SelectAction` 有效字节码所加载的 module
分别求唯一交集，并要求两席得到同一 state digest；因此
“任意 checkpoint + 不使用它的 factory”、仅挂一个未参与决策的诱饵模型，或只在编译器消除的
死分支中提及该模型都会失败。旧 PPO loader
对 normalizer 的 singleton reshape 只在这一步按名称/dtype/元素数/值等价处理；文件 hash 与 live
module config 仍分别保留精确 shape 绑定。无 checkpoint policy 的身份则只能由可检查的源码文件
descriptor 与完整、可规范序列化的 factory 配置共同计算，不能由调用者自报 hash。closure、partial
参数、mutable default、实际引用的 mutable global、同源码树内全局 helper 的 defaults/closure/globals、
callable class 的运行时配置、tensor/module state 都进入 cycle-safe config hash；跨源码树依赖至少绑定
其模块源码，无法检查的配置 fail closed。checkpoint factory 以 seat 选择不同权重也会失败。
control/treatment/official 还绑定
`treatment_id`、`replicate_id` 和 `model_seed`。manifest 的 `paired_evaluation`
声明冻结完整 policy metadata、bank payload hash、scenario 数、两席、scheduled
denominator、schedule hash 和代码 provenance hash，而不只冻结易重标的名称。

正式入口只接受 schema-v2、`running` 状态 manifest，并逐项复核：

- declaration hash、experiment/phase 和完整 evaluation binding；
- manifest 捕获的 clean/可重放 dirty-patch provenance 与代码 hash；执行前重新捕获当前
  revision，并重新计算 checkpoint、checkpoint-state attestation、policy source 与 config hash；
- `artifact_contract.scenario_banks[split]` 与实际 bank payload hash；
- 同一 declaration 内存在通过严格 schema 校验的 statistical protocol，且其中每个
  contrast component、hypothesis endpoint 与本次 candidate/opponent 身份精确相符。

因此，普通单测可直接调用单局函数，但任何正式批量评测不能绕过批准生命周期。

## 2. `episodes.jsonl[.zst]`

每行使用 `splendor-episode/1`，最小唯一键为：

```text
(candidate_sha256, opponent_sha256, scenario_id, seat, replicate_id)
```

行内同时保存：experiment/phase/batch、manifest/code/bank/schedule hash，candidate 与
opponent 全部 metadata，ScenarioV1 来源与抽样 metadata，W/D/L 和 `1/0.5/0`
score rate，raw score 与 `calScore`，plies/rounds/query/非法动作/search-node 计数，
动作类型计数，终局卡/预留/贵族/宝石 inventory，双方延迟摘要，初始化及逐决策
RNG lineage，以及逐 ply 的 seat/side/action-index/type、完整规范动作 payload、逐动作
payload hash 和 RNG digest trace；另保存完整终态的 `final_state_sha256`。
`action_trace_sha256` 由行内 trace 重算，不能替换成任意 64 位字符串。

completed row 不只做字段校验：batch audit 会从绑定的 `ScenarioV1` 重建规则实例，逐 ply
重新生成 legal action mapping，以记录的 `action_index` 取得动作并比对完整 payload，再执行
到真实终局；随后重算 raw/`calScore`、inventory 与终态 hash。因而篡改结果、动作、初态归属
或伪造“看似完整”的 trace 都不能进入统计。策略选择、引擎更新或终局汇总中的异常都转为
保留的 failed row；不会因为 finalization 再抛异常而丢失首次失败事实。

随机 opponent 的事件键故意不含 candidate/treatment/replicate：同一个
`(batch, scenario, focal seat, opponent, opponent-step)` 在所有候选间复用同一 `u53`。
候选 RNG 仍按自身 checkpoint 分离。CRN 只共享随机变元；策略分歧后状态和合法集
可能不同，不把它夸大成整局动作相同。

writer 持有文件锁并逐行 `fsync`。纯 JSONL 直接 append；zstd 使用可串接的单行 frame。
已有 key 拒绝覆盖，resume 只补原 schedule 中缺失的坐标。failed row 保留 failure
side/type/message、query/lineage/cost 事实，但 outcome/score_rate 为空；任意 failed 或
missing row 都令整个 batch `invalid`。失败不能转 loss、删除或从 denominator 排除；
代码修复后的新正式尝试必须使用新 manifest/output，旧 artifact 永久保留。

## 3. 估计量与重采样单位

实现：`policy_imitation/statistics.py`。

所有 episode 先经过严格矩形审计与上述独立回放，再在每个
`(checkpoint, opponent, scenario, replicate)` 内精确合并 seat 0/1。正式差值为：

- `checkpoint_differences`：唯一官方 checkpoint 相对 frozen `ppo-best` 的
  `d_deploy`；
- `method_differences`：同一 replicate、同一 model seed、同一场景矩阵下 treatment
  相对 O 的 `d_method`；
- `factorial_interaction_differences`：固定符号 `C - A - B + O`。

manifest 以类型化 `AnalysisContrast` 冻结每个分析的 kind、family、按身份排序的非零
零和系数，以及唯一允许参与 power 的 contrast。deployment component 必须是本次评测中的
checkpoint/source SHA；method component 必须是本次评测中的 treatment id。scenario power
只能选择 deployment contrast，model-replicate power 只能选择 method contrast，不能用换名
的合成行跨越独立性单位。两个 power contrast 还必须严格为 `+1/-1`：deployment 的正项只能是
official/treatment、负项只能是 frozen-baseline/control；method 的正项必须是 treatment、负项必须是
control，正负号对调会在 manifest 批准前失败。

方法差值拒绝同一 arm 跨 replicate 复用 checkpoint 或 model seed，也拒绝不同 arm
在同一 replicate 使用不同 model seed。差值对象继续携带 component checkpoint hash
和 model seed；nested/bootstrap/power 即使接收合成差值，也会再次审计 provenance，
不能靠手工重标 replicate 绕过。

`joint_scenario_cluster_bootstrap` 以 **scenario** 为唯一抽样 cluster。一次抽出的
scenario indices 同时作用于全部 contrast 和 opponent endpoint；不同 contrast 不会
被错误平均。双座次已在抽样前合并。Bonferroni family interval 由一次联合 draw
矩阵产生，并保存 input、scenario set 与 resample-index SHA-256。重复同一
`scenario_id` 的完全相同机械行会先折叠，不增加 scenario 数，也不会缩窄区间；同一
分析坐标但数值或 provenance 冲突的“重复”则直接拒绝。所有集合聚合前排序并使用
`math.fsum`，结果不依赖 Python hash iteration 顺序。

`nested_replicate_scenario_bootstrap` 只在至少 5 个独立 model replicates 时启用：
外层重采样 replicate，随后在每个被抽中的 replicate 内重采样 scenario；同一 inner
draw 同时保留所有 contrast/opponent/CRN 关系。各 replicate 必须使用完全相同的
scenario/endpoint/component 矩阵，且 checkpoint/model seed 均不得重复。即使 5 个
replicate 通过，输出仍固定带有小样本限制说明，并要求逐 replicate 报告。

附加摘要包括逐 replicate、均值、样本标准差、最差 replicate、opponent-stratified
IQM、performance profile 和含 tie=0.5 的 probability of improvement。Wilson 只可
作 legacy 单局描述，不能进入这些配对决策。

## 4. IID、压力集与 power

IID bootstrap 只接受 `selection_kind in {iid, ci-fixture}` 且 inclusion probability=1。
stress-balanced row 若以 IID 模式进入会直接失败；允许的输出必须显式命名为
`unweighted-diagnostic` 或使用预注册的 inverse-inclusion weighting，仍不得冒充
自然发牌 IID 结论。

`PowerAnalysisConfig` 分成两个不可互换的 unit：

- `scenario`：逐 opponent endpoint 接收 deployment scenario effects，N 强制向上取整
  为 50 的 block，默认上限 500；
- `model_replicate`：逐 opponent endpoint 接收先合并 scenario 的 replicate effects，
  scenario 再多也不能弥补 model seed 不足。

两者都固定 family-wise `alpha=0.05`、target power ≥0.8，并以 one-sided Bonferroni
`alpha* = familywise_alpha / family_size` 的正态近似作
初值，再用 centered paired empirical residual + 预注册 minimum effect 做固定 seed
模拟验证。每个 family 的固定 N 取所有预注册 opponent endpoints 所需 N 的最大值，
不允许先平均 endpoints 来人为降低方差。artifact 保存 pilot values hash、paired sample
SD、初始/向上取整 N、每个试算 N 的 power、simulation draw hash、family 推荐 N、
上限是否仍 underpowered 和限制。
scenario 设计强制 50-deal block 且正式上限不得低于 200；model-replicate 设计上限不得
低于 5，且设计下限也必须按声明的 `round_to` 向上取整。pilot effect 与最小效应必须是
`[-1, 1]` score-rate 尺度，power contrast 的正负
权重各不超过 1；零方差、NaN/Inf、比例/百分点混用、向下取整和 final outcome 后顺序
加样均不接受。

power 数据来源是 manifest 的显式二选一：

- `current-batch-pilot`：只允许未密封的 pilot/CI batch；产物标记 `prospective_use_only=true`，
  方法级 power 至少需要 3 个 model replicates；`validation-B` 与 sealed bank 的结果不能回流选 N；
- `approved-pilot-fixed-n`：manifest 必须在评测前绑定 pilot manifest hash、pilot
`statistics.json` content hash、由 pilot 完整 evaluation binding + statistical protocol 计算的
`pilot_power_design_sha256`、显式 variance-transfer protocol、固定 scenario N 与
  model-replicate N。批准时即交叉校验本次 evaluation 的 scenario/replicate 矩阵；生成最终统计时
  还要重验 pilot 的 exact matrix/protocol、analysis family、power-selected contrast/table、config、
  opponent endpoints 与推荐 N。pilot 与后续 treatment 的 checkpoint/treatment identity 可以不同，
  但只有 unit、系数尺度、decision family、opponent identity 与 power config 完全相同的显式
  `matched-unit-opponent-scale-v1` 方差迁移才被接受。最终结果只记录预注册 N 是否完整，绝不拿 final
  outcomes 重估 power。

pilot `statistics.json` 同时嵌入完整 manifest declaration，并要求其 canonical hash 与外层
`manifest_declaration_sha256`、evaluation binding、statistical protocol 三者逐项一致。最终 manifest
在批准前再绑定该 declaration hash、统计 content hash 与 power-design hash：批准后的任一处改动都会
失败。生命周期的人工批准是有意保留的信任根；若在最终批准前同步替换 declaration 和全部 hash，系统
会把它视为一个新的、尚待外部复核的 pilot，而不会把自洽 hash 当作审批签名。

本阶段没有合格的 paired crossed pilot，所以**没有伪造最终 N**。T1.4 必须先运行
`O_bridge/O × replicate × scenario × seat × opponent` pilot，再将两个 power 结果、
`delta/delta_NI`、固定 N 与 replicate 数写入并人工批准新的 immutable manifest；
在此之前不生成正式 sealed-test bank。

## 5. manifest statistical protocol

`StatisticalProtocolSpec` 将以下选择序列化成严格、可回读的
`task1-statistical-protocol-v1`：

- superiority / noninferiority / exploratory family、排序后的 endpoints、方向与唯一适用
  的 minimum-effect 或 NI margin；
- 类型化 analysis contrast、排序后的 component 系数、所属 family 与 power unit；这些
  identities 会在 manifest 批准时与 paired-evaluation candidates/opponents 交叉校验；
- tie=`1/0.5/0`、双座次先平均、失败/缺失整批 invalid、Wilson descriptive-only；
- scenario 与 nested bootstrap 的 confidence、B、seed、correction、weighting；
- scenario 与 model-replicate power 的 unit、effect、family size、alpha、power、上限、
  block、simulation B/seed；
- power source 是本 batch 的 prospective pilot，还是由哪个 pilot manifest/statistics hash
  与 exact pilot power-design hash 预先确定的固定 N，以及采用哪一个显式方差迁移契约；
- fixed-N 且 `sequential_stopping=false`，以及 stress weighting 口径。

`statistics.json` 只能从 exact running manifest、valid episode schedule 和同一统计声明
构建；builder 不接受调用者传入的分析表或 power 结果，而是从全部 canonical episode rows
内部重算 contrasts、family bootstrap 与方法摘要；只有 pilot 模式从当前 rows 计算两种 power，
fixed-N 模式则验证绑定的 pilot artifact 并禁止 post-hoc 重估。episode row 先按 schedule
规范排序再 hash，文档同时绑定 manifest declaration 与统计协议。文件 exclusive-create、
`fsync` 后设为只读，拒绝覆盖。
